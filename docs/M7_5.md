# PondGuard M7.5 — Final Hardware Simulation Package & Design-Freeze Candidate

## Purpose
M7.5 consolidates the validated M7.1–M7.4 hardware-simulation stack into a reproducible **design-freeze candidate**. The scope remains limited to hardware simulation, circuit connectivity, and electrical behavior.

## What is frozen for simulation
- M6.7 ESP32-C3 pin allocation and peripheral topology.
- ADS1115 I2C acquisition topology and channel assignment.
- Wokwi connection-level hardware simulation harness.
- DO, pH, NH3, battery-divider, and power electrical models.
- M7.3 tolerance/boundary methodology.
- M7.4 worst-case GSM transient and battery-sag policies.

## M7.4-derived freeze candidates
- GSM bulk capacitance: **4,700 uF candidate**.
- Modeled minimum robust capacitance: **3,300 uF**.
- GSM modeled burst: 2 A for 1 ms, minimum modeled rail 3.4 V.
- Battery low-OCV policy: approximately **6.4–6.8 V** before the high-load operating point becomes unsafe in the reduced-order model.
- BMS continuous-current target: **>=5 A**.

## Safety invariants
- Aerator fail-safe state: **ON**.
- DO circulation pump fail-safe state: **OFF**.
- NH3 remains qualitative; no universal dissolved-NH3 conversion is claimed.

## Reproducibility
Run:

```bash
python simulation/m7_5/finalize.py
python -m pytest -q
python tools/validate_pinmap.py
python tools/validate_m6_7.py
python tools/validate_config.py
python hardware/power/power_review.py
```

The generated `reports/m7_5/design_freeze_manifest.json` records SHA-256 hashes of the critical simulation artifacts.

## Explicit boundary
This is a **design-freeze candidate for simulation**, not a fabricated-PCB release. KiCad GUI ERC/DRC, exact PCB footprints, and procurement-hold MPN confirmations remain outside this milestone.
