# M2 — Virtual Pond + Sensor Simulation

## Goal

Create a deterministic software environment in which PondGuard can be tested
before physical hardware exists.

## Architecture

```text
Scenario JSON
     |
     v
Virtual Pond Dynamics
     |
     v
True Environmental State
     |
     v
Virtual Sensor Layer
     |
     v
Noisy / faulty observations
     |
     v
PondGuard Controller
     |
     +----> Aerator command
     |
     +----> Risk/alert reason
     |
     v
CSV experiment log
```

## M2 scope

Included:
- deterministic virtual pond
- DO dynamics
- NH3 accumulation
- pH and temperature
- accelerated simulation time
- sensor noise
- sensor failures
- scenario events
- controller interface
- crash score baseline
- aerator decision
- CSV export
- automated tests

Not included:
- ML
- real electrochemistry
- validated aquaculture kinetics
- actual ESP32 execution
- GSM hardware
- SD hardware
- KiCad
- Wokwi

## Scientific status

The virtual pond is an engineering test environment, not a validated
aquaculture model. It exists to test software invariants and controller
behavior.

The crash-score weights and thresholds are proposed baseline values. They
must not be reported as experimental or field-validated results.

## Acceptance criteria

M2 is considered complete when:
1. every supplied scenario executes successfully
2. the same random seed produces the same output
3. low DO can activate the aerator
4. sensor failure can activate the fail-safe
5. experiment results can be exported to CSV
6. controller logic remains separate from the pond model
