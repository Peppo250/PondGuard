# M3 — Experimentation & Evaluation Framework

## Goal

Turn the M2 simulator into a repeatable test bench.

M3 does not claim that the virtual pond is a scientifically validated model.
It evaluates software/controller behavior under synthetic scenarios.

## New pipeline

```text
Scenario generator
       |
       v
Synthetic pond conditions
       |
       v
M2 virtual pond
       |
       v
Virtual sensors
       |
       v
PondGuard controller
       |
       v
Evaluation metrics
       |
       v
CSV + JSON experiment report
```

## Generated experiment dimensions

The generator varies:
- initial DO
- initial free NH3
- pH
- temperature
- scenario duration
- sensor noise
- sensor failure probability
- crash event presence
- crash DO
- crash NH3

## Current event definition

A synthetic crash event is currently defined as:

`true dissolved oxygen < 4.0 mg/L`

This is an engineering test definition aligned with the project's proposed
aerator threshold; it is not a claim that 4.0 mg/L is universally lethal.

## Metrics

M3 reports:
- number of scenarios
- number of crash events
- detected crashes
- missed crashes
- false activations
- fail-safe activations
- crash detection rate
- false activation rate
- mean detection time
- mean detection lead time (positive means activation before the crash threshold)
- worst simulated DO
- maximum crash score

## Run

From the repository root:

```bash
python tools/m3_experiments.py --count 100 --seed 1234
```

Outputs:

```text
reports/m3/
├── scenarios/
├── results.csv
└── summary.json
```

## Interpretation

Do not report M3 metrics as field accuracy.

They answer software questions such as:
- Does the controller react consistently?
- Does it miss synthetic crash events?
- How often does noise produce unwanted activation?
- Does the fail-safe activate under simulated sensor failures?
- How does behavior change as the scenario space is expanded?

## Future use

The same evaluation API can later compare:
1. deterministic baseline controller
2. regression models
3. tree-based ML
4. lightweight neural models

using the same scenario/result format once real pond data becomes available.
