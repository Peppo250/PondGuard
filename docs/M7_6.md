# M7.6 — Full Automated Hardware Simulation Validation

## Objective

Turn PondGuard's existing collection of unit tests, electrical models, and Wokwi files into a **single strict evidence-producing pipeline** suitable for a project review/panel demonstration.

## One-command execution

From the repository root:

```bash
python tools/run_full_validation.py
```

The default run executes every declared stage and **repeats each Wokwi scenario twice**.

Required tools:

- Python + pytest
- PlatformIO Core (`pio`)
- Wokwi CLI (`wokwi-cli`)
- `WOKWI_CLI_TOKEN` environment variable for Wokwi CI/cloud execution

Wokwi's CLI is designed for CI, can lint diagrams, execute automation scenarios, capture serial logs, take VCD traces, and fail on missing expected behavior. The same `wokwi.toml`/`diagram.json` project configuration is shared with the VS Code simulator. See the official Wokwi CLI and automation documentation.

## Pipeline gates

1. Python regression suite.
2. Native C++ build and smoke test.
3. ESP32-C3 PlatformIO firmware build.
4. Wokwi diagram lint.
5. Eight automated Wokwi scenarios.
6. Serial telemetry parser with machine-readable `RESULT|...` records.
7. Physical-interface assertions using Wokwi `expect-pin`.
8. Two independent repeats per scenario.
9. Canonical result hashing to prove repeatability.
10. Serial logs and VCD waveform artifacts for every run.
11. SHA-256 manifest for critical source and firmware artifacts.

## Automated scenario contract

| Scenario | Demonstrates | Hard assertion |
|---|---|---|
| Nominal | Healthy pond measurement | Aerator OFF + valid telemetry |
| Hypoxia trip | Low-DO protection | DO < 4.0 + GPIO0 ON + `DO_LOW` |
| Recovery | Hysteresis recovery | Healthy DO + GPIO0 OFF |
| Battery low | Battery policy | BATTERY_LOW reason |
| Sensor fail-safe | Safety behavior | Invalid telemetry + GPIO0 ON |
| Sensor recovery | Recovery from fault | Valid telemetry + GPIO0 OFF |
| GSM + pump | Peripheral interfaces | GSM test transmission + pump GPIO pulse |
| pH envelope | Differential AFE path | pH≈4 and pH≈10 observed |

## Reproducibility policy

The pipeline does **not** report success merely because files exist or Python tests pass. A simulation run is successful only when:

- Wokwi actually executes the compiled ESP32-C3 firmware;
- the automation scenario passes its pin/serial checks;
- the firmware emits structured measurements;
- the parser confirms the expected behavior;
- the repeated run generates the same canonical measurement hash;
- logs/VCD evidence are saved.

## Panel demonstration

The panel can be shown the Wokwi circuit interactively in VS Code, while the terminal runs:

```text
python tools/run_full_validation.py
```

At the end, the panel has a reproducible report in:

```text
reports/m7_6/full_validation_report.md
reports/m7_6/full_validation_results.json
wokwi/ci/artifacts/*.serial.log
wokwi/ci/artifacts/*.vcd
```

The report is evidence for the **simulation contract**. It must not be presented as proof of physical sensor accuracy or field performance.
